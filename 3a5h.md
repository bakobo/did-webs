# qbqfst's version-string oracle has a blind spot: it asserts generated streams carry only KERI10JSON/ACDC10JSON version strings, which are EVENT BODY markers, and assemble._v1 checks serder.pvrsn -- the protocol version. Neither sees the CESR GENUS of the attachment counters, which is an independent axis. The ~3vol pin-bump attempt proved this is not theoretical: on bakobo/stack the ACDC attachment flips from a v1 '-I' SealSourceTriples to a v2 '-S' SealSourceCouples while every event body stays KERI10JSON/ACDC10JSON, so the oracle passes and only ingest.walk catches it. Wanted: extend the toolkit-wide qbqfst oracle to walk each emitted stream's attachment counters and assert every one decodes under CtrDex_1_0. That turns a v2-genus leak into a red test at the emit site instead of a confusing e.input.format.stream.f at ingest.
