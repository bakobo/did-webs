The witness angle was incidental. The real defect: ingest._signature_fails verifies a frame's controller signatures against the AID's ACCEPTED key state, and a rotation is signed by the NEW keys it announces while that state still holds the old ones -- so verifySigs finds no satisfying index and the frame is declared a forged signature. That fires for EVERY unaccounted rotation regardless of which escrow holds it: out-of-order (ooes), partially witnessed (pwes), awaiting delegation. The exclusion was already the function's stated intent in its own docstring and was simply absent from the code.

Reproduced WITHOUT witnesses, which is why this did not have to wait on ~4geu: base stream + an orphan rot (prior event absent) reported e.proof.stream.sig.f, while the identical fixture with an ixn reported e.proof.stream.frame.f. New knob dropped_rotation_candidate pins that the two agree.

WHAT REMAINS of this tick, and it is now purely the positive half: a rotation in pwes earns e.proof.stream.frame.f -- honest ('no more specific escrow attributed a cause') but vague, since the pipeline does know it is a rotation waiting for receipts. Saying so needs either phase-2 TOAD (wmoq5b) or a shared e.state.pending.witness.r promoted from heti -- which is the same estate question as ~5cue, now that didwebs has precedent for declaring a shared literal locally (see e.input.range.stream.f).
